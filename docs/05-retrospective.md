# 05 项目复盘

## 当前进展

阶段 01 建立项目结构、最小 CLI、文档入口和自动化测试基线。阶段 02 完成领域模型、稳定错误码、费用精度约定和带时区的输入校验。阶段 03 完成可复现的合成数据、四类本地业务工具、部分成功语义和确定性失败注入。阶段 04 完成步骤状态约束、执行累计值、JSON 状态持久化和带脱敏的顺序 Trace。阶段 05 完成统一模型接口、动作与工具白名单、离线 Mock、真实模型配置和双层结构校验。阶段 06 将上述组件组合为可持久化、受执行上限保护的 ReAct 闭环。阶段 07 加入预算、截止时间、重新估算和保存前硬保护，并保留每次重规划的估算证据。阶段 08 完成可重试与不可重试错误区分、失败观察反馈、受限重试、异常结构化和部分成功数据传递。阶段 09 使用输入指纹和状态查询实现无副作用重复执行与输入冲突保护。阶段 10 将这些能力集成为支持参数和 JSON 输入、目录配置、稳定退出码及机器/人类双输出的 CLI，并加入观察驱动的离线规划策略。阶段 11 用真实 CLI 子进程生成五组验收材料，以自动测试核对输出、Trace、状态、方案、动态决策和文档引用。

## 最难问题

CLI 的关键取舍是同时满足机器解析和人工查看：完整 JSON 独占标准输出，摘要写入标准错误。另一个难点是保留阶段 05 脚本化 Mock 测试兼容性的同时，为 CLI 增加真正读取状态与观察的确定性策略，因此采用两个适配器并共享同一动作校验边界。阶段 11 的难点是兼顾“原始运行证据”和“仓库可移植性”，最终只归一化临时路径，并把归一化规则与实际退出码写入运行记录。

## 学习收获

端到端入口不应绕过已验证的领域边界。CLI 只负责合并输入、配置组件和映射退出码，业务输入仍由统一校验器处理，工具动作仍由 Agent 循环和白名单保护。标准输出协议与人类日志分流后，自动化调用和交互式使用可以共享同一入口。验收材料也应可再生：生成脚本、材料和验证测试三者共同保留证据链，比只提交一份人工整理的输出更可靠。

## 已知限制

- JSON 文件存储没有跨进程并发锁，不适合作为生产级多实例 Runtime。
- 合成素材、费用和耗时只用于可复现评审，不代表真实内容平台数据。
- Trace 记录可审计的简短决策依据，不记录也不要求模型内部思维过程。
- 真实模型适配器的测试使用假客户端，不能证明账号权限、在线可用性或开放输入规划质量。
